## [0.2.0] - 2026-10-16

### Fixed

- Hiding an image takes it off any model it was the preview of, so the lock covers that picture too.
- Civitai previews are no longer fetched once Civitai is switched off; a lookup run is stopped on a server switch and its answers are stored under the server they belong to; preview downloads do not follow redirects.

### Added

- Civitai browser: the Browse Civitai button in the model library lists the newest, most downloaded or highest rated checkpoints and LoRA of the last day, week or month, filtered by base model and name. Cards show a preview, date, creator and downloads, mark models you already have (or an older version of them) and open the page in the system browser. It needs the same Civitai consent and sends no library data.
- Default VAE and text encoders per family: in the parameters panel, Use as default for <family> saves the current modules; every checkpoint of that family then starts with them (while the files are on the server), and Back to Forge's choice returns to what Forge lists.
- The LoRA gallery opens on the family of the selected model (LoRA of unknown family included); the Family filter's All shows everything.
- The side panel of the model galleries appears only when a card is selected and has its own close button.
- Settings presets: a floppy-disk menu left of the model menu applies a saved set of settings (model, modules, LoRA, size, steps, CFG, sampler, scheduler, hires, tags) while keeping the prompt, negative, seed and image count; Save current as preset… names the current settings and Manage presets… renames or deletes them (with confirmation). A preset whose model is missing on the server still applies and the model card says so. Creating, applying, renaming and deleting are logged by name.
- Select several images: Ctrl/Cmd+click toggles, Shift+click selects a range in gallery order, Space on a focused tile toggles, Esc clears. Selected tiles get a signal border and a check mark. A bar above the prompt bar counts them and offers Tags (the tags every selected image has are editable, the partial ones are shown apart and can be removed from all), Hide / Unhide, Delete (one Undo window for the whole batch, then `images:deleteMany`; images that could not be removed come back with a notice) and Clear.
- Gallery search in the top bar: free text (prompt, model, LoRA, tags) plus tag chips with suggestions (all tags must match); `/` focuses it, Esc clears the text, then the chips. While a search is on only saved images show, with a results line, Clear search and its own text when nothing matches.
- Tags on images: a tag editor in the viewer (`T` focuses it) and Tags for results in the parameters panel, so every image of a job is tagged when it is saved. Tag IPC (`tags:suggest/add/remove`).
- Reuse settings in the viewer puts the saved job (model, prompt, negative, size, steps, LoRA, seed, hires, tags) into the prompt bar.
- A model's own preview: the card lists the images generated with that checkpoint or LoRA (newest 24, visible ones only); click one to use it as the preview, the magnifier opens it in the viewer, and Remove my preview returns to Forge's or Civitai's. The viewer has Use as model preview for text-to-image results. The picture you chose survives a catalog refresh.
- Newer-version check: the Civitai lookup also asks for the model's newest version (one more request per model, cached). A card shows a "Newer version" chip, the details panel names it with Open newer version, and the filter menu lists those models.
- Duplicate finder: models that share a file hash or a Civitai version are marked "Duplicate ×N" and listed under the Duplicates filter (copies side by side); the details panel lists the other files.
- A Hires on/off switch in the prompt bar. Switching on asks which saved hires preset to use (presets whose scale would pass 4096 px are greyed out); with no preset it warns to create one first (Parameters → Hires fix → Save as preset). Switching off sets the scale to Off.
- Adding a LoRA from the gallery puts its trigger words into the prompt (your own and Civitai's lists whole; from a file's training tags only the most frequent word), skipping words already there.
- Model galleries sort by name (favorites first), recently added, release date, most used and recently used; cards show the date or the count. "Added" is when the app first saw a file (files already there at the first scan have no date); the release date comes from Civitai; use is counted from finished jobs of the server.
- Browse LoRA button next to the checkpoint gallery in the prompt bar, with the number of LoRA in use.
- Update from Civitai on a single card (needs the same consent), and Civitai trigger words for checkpoints as well as LoRA; trigger words in the details panel are buttons that add the word to the prompt.
- Optional Civitai lookup, off until you agree: Update from Civitai in the model galleries sends only each file's SHA-256 hash to civitai.com (about one a second, stoppable) and keeps the official name, base model, trigger words (they replace the file's own tags until you edit them), a preview when Forge has none, and an Open on Civitai link.
- A loading bar with the server's name replaces the model menu while checkpoints and LoRA load at start, with a hint when it takes long.
- Hires presets: save the second pass (scale, upscaler, steps, denoising, CFG) under a name, pick one to apply everything at once, delete the selected one.
- Checkpoint gallery (grid button next to the model menu): previews from Forge, search by name or folder, filters by family (with counts), favorites and folder, a details panel with path, hash, note, favorite and a hand-set model family (it decides the defaults the checkpoint starts with), Use selects the checkpoint.
- LoRA: a stack in the parameters panel (switch, weight -2..2, trigger words that insert into the prompt, remove, warnings for a LoRA that is not on the server or was made for another family) and a LoRA gallery to add from, with trigger words read from the file's training tags and editable. An enabled LoRA the server does not list fails the job as "missing on the server" before Forge is called.
- Model library groundwork: checkpoint and LoRA previews through Forge's thumb route (cached, looked up once), favorites, notes, a hand-set model family, LoRA trigger words and base family read from the file's training metadata, saved per file and server (`models:*` IPC, `fnc-model://` previews). The LoRA list timeout is now 3 minutes (a large library took 61 s). The galleries that use it follow.

## [0.1.0] - 2026-10-15

### Added

- Default negative per model family: in the negative-presets menu pick which saved negative a family starts with (e.g. Anima). Loading a checkpoint of another family (or starting the app) fills the Negative field with it; inside a family your text stays.
- Send to hires on a gallery tile: the image's own job (model, prompt, seed) runs again with a hires second pass; the dialog sets scale, upscaler, second-pass steps, denoising and CFG. Hires settings gained an optional second-pass CFG (`hr_cfg` / `hr_distilled_cfg`), also in the parameters panel.
- HD mark in the top right of images made with hires fix or upscale.
- Image viewer: zoom (buttons, +/-/0 keys, mouse wheel, drag to pan) and Show in folder.
- Clear all failed and interrupted: a broom button in the top bar removes those jobs for good.
- Image storage selection in the server dialog: choose a writable folder for future PNGs and thumbnails. Existing images keep their original paths and remain readable across folder changes and restarts; an unavailable old volume leaves its records visible. Image URLs resolve database IDs, and reads/deletes check the approved managed folders before touching a file.
- Resource monitor panel, opened by a gauge button in the top bar (it no longer sits in the bar): four ring gauges (VRAM, RAM, CPU, GPU) and the details below. VRAM and Forge-process RAM from `/memory`, one-minute graphs and peaks, model/cache VRAM, OOM count, server details and Unload/Restart controls. The optional read-only Forge extension adds CPU, system RAM, GPU activity/sensors and versions; an absent extension leaves those readings blank. The panel was checked in an isolated Electron window with mock Forge.
- Read-only Forge memory sampling while the window is visible: 60 readings stay in memory, with 2-second idle and 1-second running intervals. A sampled VRAM peak is saved with the job and its completion log; polling failures do not affect the generation queue.
- Upscale in the image viewer: choose an offered upscaler and a scale that fits the 4096-pixel limit, queue it without changing the prompt draft, and optionally save that method as the default. The hires panel can save its own default. An upscale result opens with an accessible before/after slider over the image; the source vanishes from comparison as soon as a hidden-image lock closes. The viewer flow was checked in an isolated Electron window with mock Forge.
- Upscale backend: queued jobs send a saved image to Forge's `/extra-single-image`, validate the source, upscaler and 1.5×/2×/4× scale, and save the larger result with a link to its source. Deleting the source detaches that link and keeps the result. Hires and finished-image default upscalers are stored in settings. Mock Forge and end-to-end tests cover the request, result and failures.
- Img2img from a saved image: use Send to img2img in the viewer or drag a gallery image onto the prompt bar. The bar shows the source and mode and lets you remove the source; the parameters panel has resize mode and denoising controls. The current prompt and settings remain, hires fix is paused while img2img is attached and restored when it is removed. A missing or locked source cannot be sent. The flow was checked in an isolated Electron window with mock Forge.
- Img2img backend: a saved image ID, denoising strength and resize mode are checked at enqueue; the queue reads PNG bytes from the managed image store only when the job runs and sends them to Forge's `/img2img` endpoint. A deleted, locked or unreadable source fails the job before sending; cancellation and connection recovery follow the existing queue rules. The mock Forge and end-to-end tests cover the request and saved result.
- Hires fix for txt2img: choose Off, 1.5×, 2× or 4× in the parameters panel, with an upscaler, second-pass steps, denoising strength and computed target size. The request sends Forge's hires fields only when enabled; old saved jobs remain valid.
- Gallery for thousands of images: tiles are laid out in pixels (`state/masonry.ts`) and only those within a screen above and below the view are in the DOM; the next page loads when the drawn band nears the end, and a page that failed is retried on the next scroll. Keyboard: the gallery is a single tab stop, arrow keys move between tiles, `Home`/`End` jump to the ends, `Delete` deletes the focused image with Undo and moves the focus on, and the focused tile scrolls into view above the prompt bar. A finished job's image fades in over its last live preview (260 ms, instant with reduced motion). `tools/seed-gallery.ts` fills a throwaway profile with fictional images for manual checks.
- Hidden images behind a session lock: Hide on a gallery tile (or `H` on a focused tile) marks an image hidden; the first hide asks for a password (stored only as a salted scrypt hash in `settings['lock.hash']`). While the lock is closed a hidden image is a hatched tile with a lock: main sends no address, prompt, seed or tags for it, text and tag queries skip it, the viewer's details call refuses it, and `fnc-img://` answers 404 for its file and thumbnail (also for another letter case; Windows alias spellings such as `NAME~1` or a trailing dot are refused). The lock button in the top bar opens it with the password until it is locked again or the app quits; open, hidden images carry a Hidden label and can be unhidden. The unlock dialog also changes the password (needs the current one). Five wrong passwords in a row pause attempts for 30 seconds (logged once). While locked, a hidden image's job is not readable (its prompt), the redacted record carries no job id, and the image can be neither unhidden nor deleted; its files are served with `Cache-Control: no-store` while open. Opening, closing, a wrong password and hide/unhide (image ids only) are logged.
- `images.query` IPC for filtered gallery pages (`images.list` is now an unfiltered query): page size clamped to 1..200, positive cursor, text trimmed and at most 500 characters, at most 20 tags normalised like stored tags. Tag names, tag filters, tag suggestions and text search now fold letter case beyond ASCII (Cyrillic "Кот" and "кот" are one tag, "ЗАКАТ" finds "закат"), and suggestion prefixes are trimmed.
- Forge on this PC without typing: on first start (no saved server) the app pings `http://127.0.0.1:7860` once with a short timeout and, when Forge answers, saves it as "This PC" and makes it active, so the server dialog does not open; nothing else on the network is tried. The add-server form starts with "This PC" and that address (both editable, with a Use this PC action to put the address back), and starts empty when that address is already saved. `FNC_LOCAL_SERVER` points the check at another address in dev builds.
- Generation time on display: an image's frame marking ends with the local time it was made (the date too when not today), the image viewer lists the full date and time as Created, and failed or interrupted job tiles show when they ended.
- Mouse-wheel adjustment: hovering a slider or number field (steps, images, CFG, Distilled CFG, Shift, clip skip, width, height, log retention) and turning the wheel steps its value up or down, Shift+wheel by ten steps, within its limits; the page does not scroll meanwhile, and trackpad scrolling needs a full notch's travel per step.
- Activity log panel (the plan 2 log screen, done early): opened from the top bar, newest first, with time, level, category, catalog text and duration; filters by level, category and period, a search over the shown text, live updates, export as JSON Lines through a save dialog (every entry matching the filters, read page by page, or exactly the search results while a search is active), and the retention period (1 to 3650 days, default 90) used by the start-up purge. Clicking a failed job's entry shows that job's stored error; a finished job's entry opens its image. Every message key the main process writes now has a catalog string (checked by a test).
- Recovery from a broken Forge model state: after a generation fails with HTTP 500 the app unloads the checkpoint (best effort) before the next job, so that job loads its model afresh. Two 500s in a row on one server show a notice above the prompt bar suggesting a restart; a success, a restart or a server switch clears it.
- Restart Forge and Unload model in the server dialog. Restart asks first, interrupts the running job, pauses the queue and lets the connection monitor bring the app back to Connected; it is offered only when Forge runs with `--api-server-stop` (read from `/cmd-flags` on connect), otherwise the button is disabled with a hint. A job that failed with a Forge 500 also offers Restart Forge. The mock Forge gained `unload-checkpoint`, `server-restart` (drops connections and refuses them for `RESTART_MS`), a configurable `api_server_stop` (`API_SERVER_STOP=1`) and Forge-shaped 500s (`FAIL_500=<n>|until-unload`).
- Negative-prompt presets: a menu next to the Negative toggle puts a saved negative into the field (replacing its text), saves the current negative under a name, and opens a dialog to rename or delete presets. Names are unique regardless of case; the operation log records preset names only, never their text.
- Saved Forge servers: the server dialog lists them with a name and address, adds, edits and deletes them, and switches the active one with one click (not while a job runs). The connection chip shows the active server's name. Queued jobs stay with their server; those of an inactive server show "Waiting for <name>". Deleting a server removes its queued jobs and keeps its images.
- Full-window image viewer opened from a finished gallery tile, with the saved full-resolution PNG, generation settings below it, and a Copy prompt button backed by the system clipboard.
- Gallery navigation in the image viewer with previous/next icons and Left/Right keys. Moving past the oldest loaded image fetches the next page; the counter shows the number currently loaded. The header keeps clear of Windows' caption buttons and the arrows take real mouse clicks.
- Application scaffold: Electron + React + TypeScript with electron-vite, a vitest runner that uses Electron's ABI for better-sqlite3, and a dark frameless main window.
- `tools/probe/probe.mjs`, a script that probes a live Forge instance and records its API behaviour; missing option keys are reported as `null`.
- String catalog and typed message lookup (`t()`), shared domain types, and a test that rejects user-visible string literals in renderer components.
- Design tokens, base styles, and the first UI primitives: `Button`, `IconButton`, `ParamRow`, `Select`, `Tooltip`.
- SQLite storage layer: a migrated database and repositories for servers, jobs, images and settings.
- Operation log: persisted, filterable entries that never contain prompts, with retention purge; a failed write never interrupts the operation.
- Forge HTTP client (`src/main/forge/client.ts`) with typed calls, address normalisation and one error type, plus a mock Forge server (`pnpm mock-forge`) for tests and manual runs.
- Model family profiles (`src/shared/profiles.ts`): per-family field flags and defaults, checkpoint family detection by file name, aspect-ratio dimensions and default parameters that adapt to the sampler and scheduler lists a server offers.
- txt2img request builder (`src/main/generation/payload.ts`): a pure function from generation parameters to the Forge request body, applying family profiles, LoRA tags, model modules, clip skip and shift.
- Model catalog (`src/main/forge/catalog.ts`): checkpoints, modules, LoRAs, samplers, schedulers and upscalers loaded in parallel and cached, with a check that flags a checkpoint or module a job needs but the server no longer lists.
- Image file store (`src/main/storage/image-store.ts`) writing PNGs and thumbnails under month folders, and safe `fnc-img://` image URLs (`image-protocol.ts`) that cannot resolve outside the images folder.
- Generation queue (`src/main/queue/runner.ts`): one job at a time with per-second progress and previews, cancel, retry, restart recovery, a pause while Forge is unreachable, and a failed job for a missing checkpoint or module; plus a steps-per-second helper.
- Connection status (`src/main/forge/connection.ts`): a pure state machine (connected, slow, reconnecting, offline) and a monitor that logs loss and recovery of the connection once each.
- Job errors are stored as structured codes (`JobError`) instead of sentences; the queue now fails jobs it cannot start, ends a job when 15 progress polls in a row fail, and restarts cleanly after stop.
- Typed IPC between the window and the main process (`src/shared/ipc.ts`, `src/main/ipc/register.ts`, preload bridge `window.api`): settings with a checked server address, model catalog, generation queue, image gallery and connection status, plus live events. Errors cross as stable keys, never English text. The main process now wires storage, queue, connection monitor and the `fnc-img://` image protocol together and shuts down in order (monitor, queue, log, database).
- IPC hardening: renderer-side errors carry only stable keys (`extractErrorKey`), `jobs:enqueue` validates every field and drops unknown keys, a failed file removal no longer leaves a half-deleted image, a startup failure exits instead of leaving an invisible process, shutdown waits at most 5 s for the queue, and the window is single-instance with navigation and pop-ups blocked. An opt-in smoke run (`FNC_SMOKE=1`) exercises the wiring against the mock server.
- Renderer state store (`createAppStore`, provided through `StoreProvider`): settings, connection, model catalog, generation parameters with family defaults, active jobs with progress, and the first 100 images, kept current by the main-process events. `init()` is safe to call twice.
- First screen: a 44 px top bar that doubles as the window drag area, a connection chip (state label with a coloured dot, latency or reconnect attempt), and a server dialog that opens by itself until a Forge address is set and shows a mapped, text-only error when the address is wrong. A dismissible notice shows the last failed action.
- A catalog entry for every IPC error key and `errorText()`, which turns a rejected `window.api` call into catalog text.
- Fixed the build: the `animation: :global(fade-in)` declaration in the Select and Tooltip styles was a CSS syntax error; those styles, and the new dialog, now compose a shared fade-in from `styles/motion.module.css`.
- Review fixes for the first screen: a connect that cannot refresh settings now fails visibly instead of leaving the dialog stuck, the chip reads "No server" until an address is set, a failed catalog load shows a notice with Retry (one shared `Notice` component), finished jobs are never re-added by stale responses, the dialog keeps its accessible description, and the main process samples the connection on show/restore and publishes it when the page loads.
- Prompt bar and parameters panel: a floating prompt bar (growing prompt field, Ctrl+Enter to generate, ArrowUp to recall the last prompt, optional negative prompt, checkpoint, ratio, steps and image count, Generate), a right-hand panel with the model card (each part found or not found), the sampling parameters the model family uses, seed and size, and the VAE/text-encoder list; plus a "No checkpoints found" state with Refresh and a single z-index scale in the design tokens.
- Gallery: tiles in columns (at least two, one per 226 px) with new items at the top-left. Waiting jobs have a dashed border and a queue number; the running job shows the live preview, stage, step count, speed, elapsed seconds and a 2 px progress line; failed and interrupted jobs show a message mapped from the error code (the server text below it, shortened with the full text in a tooltip), Retry and Dismiss. Finished images show the frame marking (№, seconds, size) and a Delete button on hover and keyboard focus; Delete hides the image and offers Undo for 5 seconds. Older images load 100 at a time as you scroll, and an empty gallery invites the first prompt.
- Store: `dismissJob` and `loadMoreImages` (older images, 100 at a time).
- End-to-end test of the main process (`src/main/e2e.test.ts`): the real database, image store, Forge client, catalog and queue against the mock Forge, covering a two-image run with its log entries, the server going down mid-queue and coming back, and recovery of a job left running by a previous launch.
- README: what version 0.1.0 does, where the database, images and operation log live, how to run the probe, and the known limitations.

### Changed

- The negative prompt survives a server switch like the prompt does, instead of being replaced by the new model's default; a model family without a negative prompt keeps it for the next one that has one.
- The message of a job stopped mid-run now covers both causes: the app closed or Forge restarted.
- The Restart Forge action on a failed job tile is a compact icon button (with a tooltip), and tile buttons wrap whole instead of breaking their labels.
- The negative-prompt field no longer clips by one pixel, an empty model card renders nothing, and the top bar height and the panel slide-out time come from design tokens.
- Probe findings from a real Forge Neo server: shift is sent in the `distilled_cfg_scale` field instead of an option, checkpoint previews are requested from `/sd_extra_networks/thumb`, and a checkpoint's family is detected from its whole title, folders included. New parameter sets start with the default module list the server keeps for the family.
- Steps (1-150, in the prompt bar) and CFG, Distilled CFG and Shift (in the parameters panel) are now sliders with a value readout, built on a new `Slider` primitive (Radix Slider; arrows, Page Up/Down, Home/End).
- The prompt bar fits at every window width: the Model select takes the remaining space and shortens a long checkpoint name (full name on hover), the other controls keep their size, and at narrow widths the controls move to a second line under the model instead of overflowing. The bar is up to 880 px wide and always leaves room for the open parameters panel.
- The Model menu lists checkpoints grouped by model family (SDXL, Z-Image, Qwen, Lumina, Krea 2, Anima), each group sorted by name ignoring case, with numbers in natural order.
- `pnpm mock-forge` takes `MOCK_CATALOG=many` (a long mixed-family checkpoint list with an overlong name) and `STEP_MS` (time per fake step).

### Fixed

- Dialogs are centred below the top band, so the window buttons no longer sit on top of them (the model gallery reached the top edge).
- The window buttons could cover the content: the 44 px title-bar overlay no longer matched a zoomed page, so page zoom is switched off (Ctrl+wheel, Ctrl+plus/minus/0 do nothing, and a zoom Chromium had remembered is reset at start). The viewer has its own zoom for pictures.
- A new image arrives in the gallery with the tags of its job (they showed only after a reload).
- Checkpoints without a full sha256 (Forge computes it lazily, 156 of 480 on the real server) are looked up on Civitai by Forge's short hash, which Civitai also accepts.
- Model cards show the letter placeholder while a preview loads, up to 8 previews are fetched at once, and cards of a row have equal height.
- Buttons never wrap their text (the Open on Civitai and Update from Civitai buttons overflowed in the details panel); button rows wrap whole buttons instead.
- The bottom row of the prompt bar fills every line: sliders and the other controls share the free room, and a narrow window wraps whole controls instead of clipping them.
- The loading bar at start spans the whole row up to the Generate button instead of two thirds of it, and its text wraps instead of being cut.
- An upscale that Forge never answered kept its tile running forever (extras reports no progress, so nothing ended it). A request with no answer after ten minutes is now given up and the job is interrupted, with Retry available.
- The preview in the model details panel is centred.
- Hires fix answered Forge HTTP 500 (`TypeError`) on the user's Forge Neo: it needs `hr_additional_modules` in the request. The second pass now sends `["Use same choices"]`, as Forge's own UI does. Checked against the real server for sdxl, anima and krea2 with `Latent` and a real upscaler.
- Hires fix failed ("missing on the server", and Forge HTTP 500 with a stale value) because Forge lists its latent second-pass modes (`Latent`, `Latent (nearest)`…) apart from its upscalers; the app now reads them too, defaults to `Latent`, and never offers `None` as a second-pass upscaler.
- Steps follow CFG in the prompt bar's bottom row, before the ratio.
- CFG (or Distilled CFG) is a slider in the bottom row of the prompt bar that takes the free room, so nothing is left empty under the model menu; it is no longer in the parameters panel.
- Scrollbars are thin and dark everywhere, in the colours of the UI.
- The hires settings' Save as default button no longer overflows the parameters panel (it has its own line).
- Image viewer: the area under the picture is fixed (actions and facts stay, only the prompt text scrolls), so the picture gets more room.
- The upscaler list in the image viewer could not be opened (it sat under the dialog); it now opens above it, and None and latent methods are no longer offered for a finished image.
- A hires upscaler the server does not list now fails the job as "missing on the server" instead of sending it to Forge, and a model switch replaces such an upscaler with the default.
- An upscaled image keeps the seed and infotext of its source instead of seed -1 and an empty infotext.
- The viewer's Upscale button stays visible but disabled, with a note, when the image is already at the 4096 px limit.
- A long file name in a failed job tile (missing VAE or text encoder) wraps instead of being clipped.
- Images made by img2img or upscale from a hidden image are now hidden too (they carried the hidden prompt); a retry after a crash no longer fails on a leftover file name; an upscale over the size limit reports its own error.
- A failed job now shows Forge's error message (for example `TypeError: 'NoneType' object is not callable`), not only the error class name.
- Switching checkpoints preserves the selected width and height, including custom sizes and aspect ratios; the initial checkpoint still uses its model family's defaults.
- The prompt field now appears at startup while the model catalog loads; text typed before the first model is ready is kept.
- Dropdown menus with a long list scroll (mouse wheel and keyboard) instead of running off the window; they stay inside the window and open on the selected item.
- `Ctrl+Enter` also generates from the negative-prompt field.
- The Images field in the prompt bar no longer overlaps the next control, and the running job's caption stays on one line (shortened with an ellipsis, full text on hover).
- A slow `/sdapi/v1/loras` no longer breaks the catalog: it has a 60 s timeout of its own, and when it fails the catalog loads with no LoRAs and logs a warning.
