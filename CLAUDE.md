# Forge Neo Client

Electron + React + TypeScript desktop client for the Forge Neo image-generation API. The user runs
Forge Neo on a home PC and connects from a laptop over VPN (Tailscale/WireGuard). One user, no login.

**Start every session by reading `docs/STATUS.md`** — current state, what is next, every decision
taken so far and what is waiting on the user. Talk to the user in Russian; code, comments, commits,
UI strings, README and CHANGELOG are English.

## Repository and machines

- Remote: `https://github.com/erop39/forge-simple` (**public**). Work branch `feature/core`; `main` holds the spec and plans. Pull before starting, push when a task is done.
- Git workflow and the push checklist for every agent: `AGENTS.md`. Run `node scripts/scan-private.mjs` before every push.
- **Before every push, scan everything being pushed for private data** — the user's Forge address and any LAN IPs, Windows user paths, real model/VAE/LoRA file names, emails, tokens and keys (`gh?_`, `sk-`, `AKIA`, `BEGIN … PRIVATE KEY`, passwords, `.env`), databases, images, `tools/probe/probe-report.json`. If anything is found, stop and tell the user. Docs and tests use fictional names (`exampleMix_v10`, `http://100.x.y.z:7860`).
- The detailed task ledger (`.superpowers/sdd/…/progress.md`, briefs, review reports) is git-ignored and exists only on the PC where it was written. Everything another PC needs must be in `docs/STATUS.md`.
- New PC: clone, `git checkout feature/core`, `pnpm install` (it rebuilds better-sqlite3). If `pnpm` is broken on the PATH, `scripts/start-windows.cmd` starts the app without it. Keep the checkout outside OneDrive.

## Commands

- `pnpm dev` — run the app with hot reload.
- `pnpm test` — all tests (vitest inside Electron-as-Node, so better-sqlite3 has the app's ABI). One file: `pnpm test <path>`.
- `src/main/e2e.test.ts` — end-to-end test of the main modules (real SQLite file, image store, Forge client, catalog, runner) against the mock Forge, without Electron; runs as part of `pnpm test`.
- `pnpm typecheck` — renderer/main/preload and Node-side config.
- `pnpm build` — production build. **Run it before every commit**: vitest does not compile CSS modules, so CSS errors only show up here.
- `pnpm mock-forge` — fake Forge on port 7861 (`PORT=<n>` to change; 7861 is often taken). `STEP_MS=<ms>` slows the fake steps; `MOCK_CATALOG=many` serves ~55 fictional checkpoints across families (with an overlong name) for menu and layout checks; `API_SERVER_STOP=1` accepts `server-restart` (drops all sockets, refuses connections for `RESTART_MS`, default 1500, then listens again); `FAIL_500=<n>|until-unload` makes generations fail with Forge-shaped 500s. In tests: `failGenerations()`, `setApiServerStop()`, `stats()`. Used by tests and for manual runs.
- `node tools/probe/probe.mjs http://HOST:7860` — read-only probe of a real Forge; writes `tools/probe/probe-report.json` (git-ignored, holds private paths).
- `ELECTRON_RUN_AS_NODE=1 node_modules/.bin/electron node_modules/tsx/dist/cli.mjs tools/seed-gallery.ts <user-data-dir> [count] [server-url]` — fills a throwaway profile (e.g. under `out/`) with fictional images and an active server, for checking the gallery with hundreds of tiles; delete the folder afterwards.

## Smoke run

`FNC_SMOKE=1` (dev builds only) loads `src/main/fnc-smoke.ts`, which drives `window.api` against a mock Forge, prints one `FNC_SMOKE {...}` JSON line and quits. Build first, start `PORT=7871 pnpm mock-forge`, then:
`FNC_SMOKE=1 FNC_SMOKE_SERVER=127.0.0.1:7871 node_modules/.bin/electron . --user-data-dir=<temp dir>`. Always use a throwaway `--user-data-dir`.

## Manual check in the real window

`pnpm build`, then a slow mock so progress is visible: `STEP_MS=300 PORT=7881 pnpm mock-forge`, then `node_modules/.bin/electron . --remote-debugging-port=<port> --user-data-dir=<temp dir>` and drive or screenshot the page over CDP (`http://127.0.0.1:<port>/json`). The window opens on the user's desktop: tell the user before starting, and stop both processes afterwards.

**Never drive a window you did not start.** Another window of this app (the user's, or another session's) may already hold a CDP port; if yours cannot bind it, Electron only logs an error and keeps running, and `/json` then answers from the other window. Pick an unusual port, check it is free first, and after start confirm that the process listening on it is yours (its command line has your `--user-data-dir`). A window behind others is `visibilityState: hidden` and renders no frames: transitions, `ResizeObserver` and `requestAnimationFrame` stall and CDP input waits for a frame; each `Page.captureScreenshot` forces one. `Emulation.setDeviceMetricsOverride` (for window widths) lasts only while that CDP connection is open.

## Layout

- `src/main/` — owns all state. `forge/` (HTTP client, catalog, connection monitor, active-server holder, probe findings), `generation/payload.ts` (params → txt2img/img2img bodies), `queue/` (runner, speed), `storage/` (SQLite, repos, image files, managed source-image reads, `fnc-img://` resolver), `oplog/` (operation log), `ipc/register.ts` (every IPC handler), `index.ts` (Electron wiring, protocol, window).
- Servers: saved in `servers`; removal is soft (`removed_at`), and `repos.servers.get/list/active` never return removed rows (jobs and images keep pointing at them). IPC `servers:list/add/update/remove/activate/addLocal` (the old `settings:setServerUrl` is gone). `servers:addLocal(name)` is the first-run check: only with no saved server, one ping (1.5 s timeout) of `IpcDeps.localUrl` (default `LOCAL_FORGE_URL`, `http://127.0.0.1:7860`; dev builds take `FNC_LOCAL_SERVER=<url>` to point it at a mock), saved and activated when it answers as Forge; the store calls it in `init()` before setting `settings`, so the server dialog does not flash. `settings:get` also returns `localUrl`, which prefills the add-server form. Main pushes `servers` and `job:removed` events. Every change of the active server goes through `activeServerChanged` in `ipc/register.ts`. In the renderer, async results carry a revision (`partsSeq`, `selectSeq`, `catalogSeq` in `store.ts`) so a late response can never overwrite a newer choice — keep that pattern for new async state.
- Negative presets: table `negative_presets` (migration 3, names unique `COLLATE NOCASE`), `repos.negativePresets`, IPC `negativePresets:list/add/update/remove` (a taken name is `error.presetNameTaken`); the log (category `preset`) carries names only. Renderer: `components/NegativePresetMenu.tsx` (menu, reuses the `ui/Select` content and item classes) and `NegativePresetDialogs.tsx`; `store.negativePresets` reloads after each change under `presetsSeq`.
- Forge control and recovery: a generation HTTP 500 makes the runner call `unloadCheckpoint()` (best effort, `log.recovery.unloaded`/`unloadFailed`) before the next job; `UNHEALTHY_AFTER` (2) 500s in a row on one server set the runner's unhealthy flag (event `forge:health`), cleared by a success, `runner.resetHealth()` (server switch) or a restart. `runner.restartForge()` sends `server-restart`; on `restarting` it interrupts the running job (code `stopped`; a network drop while the request is out counts the same) and pauses the queue (`log.queue.paused` reason `restart`). `forge/capabilities.ts` reads `/cmd-flags` (`api_server_stop` → `canRestart`) on each reconnect and after a server switch (event `forge:capabilities`). IPC `forge:capabilities/health/restart/unload` (unload refused with `error.jobRunning` while a job runs); log category `server` with name and address only. Renderer: `ForgeRestart.tsx` (`RestartConfirm`, shared by the server dialog and `RestartDialog`, which `store.askRestart()` opens from a 500 tile or the unhealthy notice in the prompt bar).
- Operation log panel: `createOplog(db, now, onAdded)` pushes each stored entry as event `oplog:added`; IPC `oplog:list/export/retention/setRetention` (export pages through every match with the `before` cursor, or takes the panel's search results as `ids`, and writes JSON Lines via the injected `chooseExportPath` save dialog; the log keeps only the file name; retention lives in `settings['oplog.retentionDays']`, 1..3650, default 90, used by the start-up purge) and `jobs:get`. Renderer: `components/LogPanel.tsx` (store `logOpen`, `logEntries`, `logFilters` under `logSeq`; text search runs on the translated text), `i18n/log-text.ts` fills a message from the entry's details. Every `'log.x.y'` key in `src/main` must have a string in `en.ts` (`i18n/log-keys.test.ts`). A failed job's Forge text is shown from the job row, never copied into the log. `store.requestView(imageId)` asks `Gallery` to open an image in the viewer.
- Gallery queries and tags: `storage/image-query.ts` builds `images.query` SQL; `openDb` registers the deterministic SQLite function `ulower` (Unicode `toLowerCase`), used for tag identity, tag filters, suggestions, text search and the hidden-file check, because NOCASE/LIKE fold ASCII only. IPC `images:query` validates through `validateImageQuery` (limit clamped 1..200, positive `beforeId`, text ≤ 500 trimmed, ≤ 20 tags normalised by `normalizeTag`); `images:list` is an unfiltered query. `toRecords` in `ipc/register.ts` adds tags (one `tags.forImages` query per page).
- Hidden images: `lock/lock.ts` (`createLock(settings, oplog)`: scrypt hash in `settings['lock.hash']`, open state in memory only, so every start is locked; refusals are `LockError` with an IPC key). While locked, main redacts hidden rows (`locked: true`, see `toImageRecord`), leaves them out of text/tag queries, `images:details`, `jobs:get` (for the job of a hidden image), unhiding and `images:delete` answer error.notFound, the redacted record has `jobId: 0`, and the production `fnc-img://local/image/<id>` / `thumb/<id>` handler looks up the DB row and answers 404 for a hidden image (and `Cache-Control: no-store` while open); five wrong passwords in a row lock out for 30 s (`error.tooManyAttempts`); `close()` bumps an epoch so an in-flight `open()` cannot reopen. The old path resolver remains for isolated tests and rejects `~` and trailing dots/spaces. Hiding needs a password (`error.noPassword`). IPC `lock:state/open/close/setPassword`, `images:setHidden`; events `lock` and `images:changed`. Renderer: `LockButton` (top bar), `LockDialog` (modes set/open/change, `store.lockDialog`), locked/hidden tiles in `ImageTile` (`--hatch` token). On `lock`/`images:changed` the store covers hidden images (and ids changed since the last reload) locally at once (`lockedCopy`) and reloads every loaded page under `imagesSeq`; the first page in `init` and `loadMoreImages` drop an answer that started before a reload.
- `src/preload/index.ts` — exposes exactly the `Api` from `src/shared/ipc.ts` as `window.api`.
- `src/shared/` — `types.ts`, `ipc.ts` (Api, channels, `IpcErrorKey`), `profiles.ts` (model families; imported by main and renderer, no Node imports).
- `src/renderer/` — React. `state/store.ts` (zustand, provided via `StoreProvider`; `state/gallery-items.ts` merges jobs and images; `state/masonry.ts` places them in pixels (`placeItems`), picks the tiles in a band (`visibleSlice`) and the keyboard neighbour (`neighbour`); `state/checkpoint-options.ts` builds the family-grouped Model menu), `components/` (+ `ui/` primitives — `Select` takes `grow` and grouped options, `Slider` wraps Radix Slider; `Slider` and `NumberField` step their value with the mouse wheel through `ui/use-wheel-step.ts` (callback ref + native non-passive listener; a line/page event or a pixel delta of 50 px or more is one notch, smaller trackpad deltas add up to 100 px per step; Shift = 10 steps; a value outside the range never moves the wrong way); `use-pending-delete.ts` drives delete-with-undo; `use-reveals.ts` the job → image crossfade). `Gallery` is virtualized: absolutely placed slots (`data-key`, `data-column`) only for tiles within one screen above and below the view, plus the tile holding the single roving tab stop (tiles take `tabStop`, and mark their focus target `data-primary`); paging is a distance check on scroll, not an observer, `format.ts` (shared display formatters: `baseName`, `frameCaption`, `shortTime`/`fullTime` via Intl with `LOCALE` from `i18n/t.ts`), `locales/en.ts`, `i18n/`, `styles/` (`tokens.css`, `base.css`, `motion.module.css`). The prompt bar publishes its height as the root CSS variable `--prompt-bar-h`; floating content pads by it.
- `tools/mock-forge/server.ts`, `tools/probe/probe.mjs`, `tools/seed-gallery.ts`.
- The prompt field renders before the model catalog arrives. `state/store.ts` keeps early text in `draftPrompt` and transfers it into the first selected model's parameters; model controls and Generate wait for that model. `draftNegative` does the same for the negative prompt across a server switch (null until a family with a negative was chosen; a family without one leaves it untouched).
- Hires fix is optional in persisted `GenerationParams` so old jobs remain readable. `defaultParams` supplies Off with a catalog upscaler, IPC validates the selected scale and 4096-pixel target bounds, and `generation/payload.ts` sends hires fields only when enabled. The parameters panel shows the target size and second-pass controls.
- Img2img jobs use optional `GenerationParams.img2img` (source image ID, denoising strength, Forge resize mode 0..3). `jobs:enqueue` validates the ID and session lock; `runner` checks again when the queued job runs, reads and validates PNG bytes only via `image-store.readSource()`, and dispatches to `/img2img`. Source bytes are never persisted in params, errors or the operation log; arbitrary Forge error details are omitted for img2img. The lock is also checked on retry. A source removed, hidden behind a closed lock, or unreadable when the job reaches the queue fails with a source error code. The managed image directory is app-owned and must not be modified by another process during a read.
- Renderer img2img entry: `ImageViewer` calls `store.attachImageSource(id)` and closes, and a gallery tile drags its numeric ID with `application/x-forge-neo-image-id` onto `PromptBar`. The store accepts only a currently visible, unlocked image, preserves prompt and settings, pauses hires, and restores it when the source is removed. `PromptBar` shows the source; `ParamsPanel` shows resize mode and denoising. Generate checks the source still exists and is unlocked before IPC, while main repeats the check. External file drops are not implemented.
- Upscale jobs use optional `GenerationParams.upscale` (saved source ID, upscaler, scale 1.5/2/4). Main validates source, lock, catalogue name and 4096-pixel bounds, then the runner reads the managed PNG and calls `/extra-single-image`. The response is stored as an image with `source_image_id`; `images.delete` clears references to a deleted source in its transaction, so derived images stay. Source bytes and arbitrary Forge errors do not enter jobs or the log. `settings:setUpscalers` saves preferred hires and finished-image upscalers, and `catalog:defaults` uses the hires choice when offered by the active server. The viewer queues upscale without changing the prompt draft, allows saving the finished-image default, and compares source/result with a keyboard-accessible slider. Hires has a separate Save as default control. Comparison rechecks `images:details` when the session lock changes and covers a hidden source immediately on lock close.
- `forge/resources.ts` parses the read-only `/memory` response into nullable metrics and holds the latest 60 samples in memory. Main runs it only while its own window is visible, at 2 s idle or 1 s while a job runs; a server switch drops old samples and in-flight replies. Failed memory polls only mark the resource reading stale. `queue/runner.ts` consumes the sampled system-VRAM peak on a terminal job state, persists it in `jobs.peak_vram`, and includes it in a successful generation log entry.
- `forge/stats.ts` parses the optional `GET /forge-neo-client/v1/stats` response. `forge/resources.ts` probes it once on each healthy connection and adds readings to subsequent samples; HTTP 404 leaves `/memory` sampling alone. Main emits `resources` snapshots (also after renderer reload). `Resources` in the top bar shows four meters and a detail panel with a one-minute graph, peaks, model/cache VRAM, server and control actions. `forge-extension/forge-neo-client-stats/scripts/forge_neo_client_stats.py` registers the read-only route through Forge's `on_app_started` callback. It was syntax-checked locally and must be installed manually on the Forge PC; it has not run on the user's Forge.
- Image storage selection: `settings:chooseImagesDir` opens Electron's native folder picker, resolves the chosen directory, tests a write, and only then stores `imagesDir` plus the append-only `images.roots` list. `storage/image-store.ts` writes new files to the active root but checks all approved roots for old-source reads and file deletion; it rejects paths outside them and symlinked parent paths. Renderer image URLs are DB IDs, so `storage/image-protocol.ts` resolves the stored path through the row, enforces the session lock and checks the real path against an approved root. A missing old volume returns 404, retaining the DB row. The folder picker does not move old files. Keep the DB and every used image folder for backups.
- A finished image opens `ImageViewer` from `Gallery`. `images:details` reads the persisted image and job parameters; `clipboard:writeText` copies via Electron main. See `docs/image-viewer.md`.
- The viewer and top bar reserve `--w-caption-controls` on the right for Electron's Windows title-bar overlay; interactive controls inside that area look visible but do not receive real clicks. The viewer's `.actions` also needs `-webkit-app-region: no-drag` because the draggable top bar underneath otherwise swallows physical mouse clicks on the arrows. DevTools clicks do not catch this.

## Rules

- Every commit that changes behaviour adds a line under `## [Unreleased]` in `CHANGELOG.md` and keeps `README.md` accurate.
- **This file and `docs/STATUS.md` are part of the work**: update `CLAUDE.md` in the same commit that changes a command, convention or layout; update `docs/STATUS.md` whenever a task finishes, a decision is taken, or something starts waiting on the user.
- Every user-visible string goes through `t()` and lives in `src/renderer/locales/en.ts`; no display literals in JSX or in main. A guard test (`src/renderer/i18n/no-literals.test.ts`, AST-based) enforces it, including in tests.
- Errors cross boundaries as codes, never sentences: jobs carry `JobError { code, status?, detail?, missing? }`; rejected IPC calls carry exactly one `IpcErrorKey` (the preload unwraps Electron's wrapper). The renderer maps codes to catalog text.
- All HTTP to Forge is made from main. The renderer runs with `contextIsolation`, `sandbox`, no `nodeIntegration`; images reach it only through `fnc-img://` (CSP allows it in `img-src` only).
- Prompts never reach the operation log, and neither does Forge's error text for a generation (it may echo the prompt).
- Styling: only CSS variables from `tokens.css` (colours, spacing, radii, durations, heights, z-index); text ≥ 12 px; weights 400/500; no uppercase; animate only `transform`/`opacity`; shared fade via `composes: fadeIn from '…/motion.module.css'` (never `:global()` in an animation shorthand — it breaks the build); a signal colour is never the only indicator. No UI kits; Radix Primitives and Phosphor icons only.
- Never commit the user's real file paths or model file names (from probe reports or their Forge); use fictional examples of the same shape.
- Write text containing backslashes (Windows paths) with the Edit/Write tools, not shell `sed`/`echo`/heredocs/inline scripts: sequences like backslash-f get turned into control bytes (this corrupted the `%APPDATA%\forge-neo-client` path in README twice). Before committing docs, check: `grep -nP '[\x00-\x08\x0B\x0C\x0E-\x1F]' *.md docs/*.md` must print nothing.
- Tests live next to the code (`x.ts` → `x.test.ts`); TypeScript strict; aliases `@shared/*`, `@main/*`, `@renderer/*`. Write the failing test first.

## Working method

Default (since 2026-10-15, to cut cost — the user asked for it): **one session on a mid-tier model (Sonnet) implements tasks itself** with superpowers:executing-plans — test first, `pnpm build` / `typecheck` / `test`, docs, commit — and does **not** spawn a subagent per task.

- Review: one reviewer subagent per finished milestone (a plan's batch of 3–5 tasks or a risky change such as anything touching the lock, IPC validation or file paths), on a mid-tier model, given a single diff file (`git diff -U5 BASE..HEAD > file`). Use the most capable model only for a plan's final whole-branch review or security-sensitive code.
- Fix review findings yourself in the same session, then commit; re-review only Critical/Important fixes.
- Keep context small: read files by line range, grep before reading, don't paste large outputs, don't re-run the full suite when one test file covers the change (run the full suite once before each commit).
- Keep reports and replies to the user short.
- Record decisions directly in `docs/STATUS.md` (Decisions section). The old per-task ledgers in `.superpowers/sdd/` are optional local notes.
- Superpowers subagent-driven-development (implementer + reviewer per task) remains available for large, unclear tasks; use it only when the user asks.
