# Forge Neo Client — спецификация v1

Дата: 2026-10-13. Статус: на ревью.

## 1. Цель

Десктоп-клиент для ноутбука, который подключается по VPN (Tailscale/WireGuard) к Forge
Neo на домашнем ПК и даёт удобную генерацию изображений без штатного Gradio-интерфейса.

Пользователь один. Аутентификации в приложении нет: защитой служит VPN.

Критерий успеха: с ноутбука вне дома проходит сценарий «выбрать чекпоинт в галерее →
сгенерировать → видеть прогресс → результат в истории → повторить из истории → апскейл».

## 2. Объём

В v1 входит:
- txt2img и img2img (без маски);
- hires fix и апскейл готовой картинки;
- галерея чекпоинтов с превью;
- выбор VAE и текстовых энкодеров;
- LoRA с весами;
- пресеты настроек;
- очередь задач;
- галерея и история результатов с поиском и тегами;
- скрытие отдельных картинок под замок;
- журнал операций.

Семейства моделей: SDXL (включая Illustrious и Pony), Z-Image, Qwen-Image, Lumina,
Krea 2, Anima.

В v1 не входит: inpaint с маской, ControlNet, видео (Wan), X/Y-сетки, логин и роли,
вёрстка под телефон, синхронизация истории между устройствами, управление самим Forge
(запуск, перезапуск, установка моделей).

## 3. Требования к Forge Neo

Forge на домашнем ПК запущен с флагами `--api --listen`. Клиенту нужен только его адрес,
например `http://100.x.y.z:7860`.

## 4. API Forge Neo

Проверено по исходникам ветки `neo` (`modules/api/api.py`, `modules/processing.py`,
`modules/ui_extra_networks.py`, `extensions-builtin/sd_forge_lora`).

| Назначение | Запрос |
|---|---|
| Генерация | `POST /sdapi/v1/txt2img`, `POST /sdapi/v1/img2img` — синхронные, ответ содержит картинки в base64 и `info` |
| Прогресс | `GET /sdapi/v1/progress` → `progress`, `eta_relative`, `state`, `current_image` |
| Отмена | `POST /sdapi/v1/interrupt` |
| Чекпоинты | `GET /sdapi/v1/sd-models` → `title`, `model_name`, `filename`, `hash` |
| VAE и энкодеры | `GET /sdapi/v1/sd-modules` → `model_name`, `filename` (один общий список) |
| LoRA | `GET /sdapi/v1/loras` → `name`, `alias`, `path`, `metadata` |
| Сэмплеры, планировщики, апскейлеры | `GET /sdapi/v1/samplers`, `/schedulers`, `/upscalers` |
| Настройки сервера | `GET /sdapi/v1/options` |
| Апскейл картинки | `POST /sdapi/v1/extra-single-image` |
| Превью модели | `GET /sd_extra_networks/thumb?filename=<абсолютный путь к файлу превью>` |

Поля запроса генерации, которые использует клиент: `prompt`, `negative_prompt`, `steps`,
`cfg_scale`, `distilled_cfg_scale`, `sampler_name`, `scheduler`, `width`, `height`,
`seed`, `batch_size`, `n_iter`, `enable_hr`, `hr_scale`, `hr_upscaler`,
`hr_second_pass_steps`, `denoising_strength`, `hr_additional_modules`, `init_images`,
`resize_mode`, `override_settings`.

Чекпоинт, модули и clip skip передаются в `override_settings`: `sd_model_checkpoint`,
`forge_additional_modules`, `CLIP_stop_at_last_layers`.

LoRA подключается текстом в конце промпта: `<lora:имя:вес>`.

Отдельного эндпоинта для превью нет. Файл превью лежит рядом с моделью под именем
`<имя>.<ext>` или `<имя>.preview.<ext>`, где `ext` — `png`, `jpg`, `jpeg`, `webp`.
Клиент перебирает эти варианты через `/sd_extra_networks/thumb` и кэширует найденный.

### Открытые вопросы к живому серверу

Forge стоит на другой машине, поэтому три пункта проверяются отдельным скриптом-пробой
до начала реализации; спека уточняется по его выводу.

1. Как называется опция `shift` и параметры новых архитектур в `/options`.
2. Отвечает ли `/sd_extra_networks/thumb` при запуске с `--api`. Если нет, галерея
   чекпоинтов показывает карточки без картинок, а превью пользователь назначает сам из
   своих результатов.
3. Что принимает `forge_additional_modules`: имена из `/sd-modules` или полные пути.

## 5. Архитектура

Стек: Electron, Vite, React, TypeScript, pnpm, vitest, better-sqlite3.
Интерфейс: CSS Modules и CSS-переменные, без готовых наборов компонентов. Подробности в
разделе 11.

Все HTTP-запросы к Forge идут из main-процесса. Renderer не знает адрес Forge и общается
с main через типизированный IPC, объявленный в preload.

### Модули main-процесса

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `forge/client` | Типизированные вызовы эндпоинтов Forge, таймауты, приведение ошибок к одному типу | `fetch` |
| `forge/catalog` | Списки чекпоинтов, модулей, LoRA, сэмплеров, планировщиков, апскейлеров; кэш в памяти; поиск превью | `forge/client` |
| `generation/profiles` | Профили семейств моделей | — |
| `generation/payload` | Чистая функция `GenerationParams → тело запроса Forge` | `generation/profiles` |
| `queue/runner` | Последовательное выполнение задач, опрос прогресса, отмена, повтор | `forge/client`, `storage` |
| `storage` | SQLite и файлы картинок в `userData` | better-sqlite3 |
| `oplog` | Запись событий в журнал операций, выборка с фильтрами, экспорт | `storage` |
| `ipc` | Регистрация IPC-обработчиков | все перечисленные |

### Профили семейств

Профиль — это данные: какие поля формы показывать и какие значения ставить по умолчанию.

| Семейство | Негатив | CFG | Distilled CFG | Shift | Clip skip | Модули |
|---|---|---|---|---|---|---|
| SDXL | да | да | нет | нет | да | VAE по желанию |
| Z-Image | да | да | нет | да | нет | энкодер + VAE |
| Qwen-Image | да | да | нет | да | нет | энкодер + VAE |
| Lumina | да | да | нет | да | нет | энкодер + VAE |
| Krea 2 | нет | нет | да | нет | нет | энкодеры + VAE |
| Anima | да | да | нет | да | нет | энкодер + VAE |

Точные значения по умолчанию и набор полей для новых архитектур фиксируются после пробы
API (вопрос 1). Таблица выше — исходная гипотеза, а не проверенный факт.

Семейство чекпоинта определяется по имени файла (`illustrious`, `pony`, `xl`, `z_image`,
`qwen`, `lumina`, `krea`, `anima`). Если совпадений нет, ставится SDXL. Пользователь
меняет семейство вручную в галерее чекпоинтов; выбор сохраняется в SQLite по `filename`.

### Данные

SQLite-файл в `userData`:
- `jobs` — id, тип (`txt2img`, `img2img`, `upscale`), параметры (JSON), статус
  (`queued`, `running`, `done`, `failed`, `interrupted`, `cancelled`), текст ошибки,
  время создания и завершения;
- `images` — id, job id, путь к файлу, путь к миниатюре, сид, infotext, время, длительность
  генерации, признак «скрыта», id исходной картинки (для результата апскейла);
- `tags` — id, имя; `image_tags` — image id, tag id;
- `presets` — id, имя, параметры (JSON), теги по умолчанию;
- `checkpoint_meta` — filename, семейство, путь к найденному превью;
- `settings` — ключ, значение;
- `oplog` — id, время, уровень, категория, сообщение, длительность в мс, job id,
  детали (JSON). Подробности в разделе 9.

Картинки сохраняются PNG-файлами в папку из настроек (по умолчанию `userData/images`).
Миниатюры делаются средствами Electron (`nativeImage`) при сохранении.

### Интерфейс

Образец — HEISS UI (heiss-ui.vercel.app): интерфейс строится вокруг галереи. Тема только
тёмная. Экран один; всё остальное — панели и окна поверх него.

**Главный экран.** Галерея плиткой разной высоты на всё окно, новые картинки сверху.
- Задача появляется плиткой сразу после постановки. У ждущей — пунктирная рамка и
  кнопка «Отмена». У идущей — пиксельное живое превью, счётчик шагов, прошедшее время,
  полоса прогресса и «Отмена». По завершении плитка становится картинкой на том же месте.
- На плитке готовой картинки при наведении: время генерации, теги, кнопка скрытия.
- Картинки можно выделять по нескольку для действий пачкой: теги, скрыть, удалить.
- Результат апскейла и его исходник показываются одной плиткой.

**Верхняя строка.** Слева поиск по промпту, модели, LoRA и тегам. Справа индикатор связи
с Forge, замок скрытых картинок, кнопки журнала и настроек.

**Панель промпта.** Плавает внизу по центру поверх галереи. В ней: поле промпта,
раскрывающийся негатив, выбор пресета или чекпоинта, соотношение сторон, шаги, число
вариантов, LoRA, кнопка «все параметры», кнопка запуска. Стрелка вверх в пустом поле
подставляет предыдущий промпт. Для img2img исходная картинка перетаскивается на панель
или отправляется из просмотра.

**Боковая панель параметров.** Выезжает справа. Сверху карточка модели: чекпоинт и
нужные ему энкодеры и VAE, у каждого статус «есть в Forge» или «не найден». Недостающее
клиент не скачивает. Ниже параметры по профилю семейства (сэмплер, планировщик, CFG или
distilled CFG, shift, clip skip, сид, размер), блок апскейла, стек LoRA с весами, теги
для результатов и кнопка «Сохранить как пресет».

**Галерея чекпоинтов.** Окно поверх экрана, открывается из панели промпта. Сетка
карточек с превью, поиск по имени, смена семейства, кнопка «использовать».

**Просмотр картинки.** На весь экран. Параметры генерации, время, теги. Действия:
сохранить как, удалить, скрыть, апскейл, «повторить с этими настройками», «отправить в
img2img». Для результата апскейла — ползунок «до / после».

**Пресеты.** Список в выпадающем меню панели промпта: применить, переименовать, удалить.
Пресет хранит чекпоинт, модули, параметры, стек LoRA и теги по умолчанию, но не промпт.

**Журнал.** Боковая панель. Таблица событий, новые сверху. Фильтры по уровню, категории
и периоду, поиск по тексту, переход от события к связанной задаче, экспорт в файл.

**Настройки.** Боковая панель. Адрес Forge, проверка соединения, папка для картинок,
срок хранения журнала, пароль замка.

### Апскейл

Два способа, оба штатные для Forge.

- **В том же прогоне.** Переключатель «Нет / 2× / 4×» в боковой панели включает hires
  fix: поля `enable_hr`, `hr_scale`, `hr_upscaler`, `hr_second_pass_steps`,
  `denoising_strength`. Картинка дорисовывается в большем размере и получает новые
  детали. Доступен только для txt2img.
- **Для готовой картинки.** Кнопка в просмотре ставит задачу типа `upscale`, которая
  вызывает `/extra-single-image` с выбранным апскейлером и множителем. Детали не
  добавляются. Результат сохраняется отдельной картинкой со ссылкой на исходник.

Список апскейлеров берётся из `/upscalers`. Апскейлер по умолчанию для каждого способа
задаётся в настройках.

### Теги

Тег — произвольная строка без учёта регистра. У картинки может быть любое число тегов.
- Теги назначаются в просмотре картинки и пачкой по выделению в галерее.
- Теги, указанные в боковой панели или в пресете, ставятся на все результаты задачи.
- В поиске теги выбираются из подсказки; несколько тегов сужают выборку (логическое И).
- Тег, не привязанный ни к одной картинке, удаляется автоматически.

Модель, LoRA и дата тегами не являются: поиск находит по ним из параметров задачи.

### Скрытые картинки

Скрытие защищает от случайного взгляда на экран, а не от доступа к файлам: PNG остаются
обычными файлами в папке картинок, шифрования нет. README говорит об этом прямо.

- Любую картинку можно пометить скрытой: в просмотре, с плитки или пачкой.
- При закрытом замке на месте скрытой картинки плитка с замком без превью. Её промпт и
  теги не показываются и не находятся поиском; в журнале связанные события видны без
  перехода к задаче.
- Замок открывается паролем на время сеанса и закрывается кнопкой или при выходе из
  приложения. При открытом замке скрытые картинки видны с меткой.
- Пароль задаётся в настройках при первом скрытии. В базе хранится только его хеш
  (scrypt с солью). Смена пароля требует старый пароль.
- Забытый пароль сбрасывается удалением записи из настроек; картинки при этом не теряются.

## 6. Поток данных

1. Пользователь нажимает «Сгенерировать». Renderer отправляет `GenerationParams` в main.
2. Main записывает задачу в `jobs` со статусом `queued`.
3. `queue/runner` берёт самую старую задачу `queued`, ставит `running`, собирает тело
   запроса через `generation/payload` и отправляет его в Forge.
4. Пока запрос выполняется, runner раз в секунду опрашивает `/progress` и пересылает
   прогресс и превью в renderer.
5. По ответу runner сохраняет картинки и миниатюры, пишет строки в `images`, ставит
   задаче `done` и берёт следующую.

Одновременно выполняется одна задача: Forge всё равно обрабатывает запросы по очереди.

## 7. Обработка ошибок

- **Forge недоступен.** В шапке баннер со статусом. Очередь встаёт на паузу, runner
  проверяет связь каждые 5 секунд и продолжает сам. Задачи остаются `queued`.
- **Связь оборвалась во время генерации.** Задача получает `interrupted`, очередь встаёт
  на паузу как выше. Автоповтора нет: повтор запускает пользователь.
- **Forge вернул ошибку.** Задача получает `failed` с текстом ошибки, очередь идёт дальше.
- **Отмена.** Для `running` — `POST /interrupt`, статус `cancelled`. Для `queued` —
  только смена статуса.
- **Приложение закрыли во время генерации.** При запуске все `running` становятся
  `interrupted`.
- **Чекпоинт, модуль или LoRA из параметров отсутствует на сервере.** Проверка по
  каталогу до отправки; задача получает `failed` с названием пропавшего файла.

## 8. Тестирование

Юнит-тесты на vitest, пишутся до кода:
- `generation/payload` — по тесту на каждое семейство, hires fix, img2img, LoRA;
- `generation/profiles` — определение семейства по имени файла;
- `forge/catalog` — перебор вариантов имени превью;
- `queue/runner` с поддельным клиентом — успех, ошибка, отмена, обрыв связи, пауза и
  возобновление;
- `storage` — на временной базе, включая теги и фильтр скрытых;
- замок — проверка пароля, выдача скрытых картинок только при открытом замке.

Интеграционные тесты: `forge/client` против локального HTTP-сервера, который отдаёт
записанные ответы Forge.

Ручная проверка по VPN на настоящем Forge: по одной генерации на каждое семейство,
img2img, hires fix, апскейл, LoRA, отмена, обрыв связи посреди очереди.

## 9. Журнал операций

Каждая операция приложения оставляет запись в таблице `oplog`. Запись делает модуль,
который выполнил операцию, через единственную функцию `oplog.write`; напрямую в таблицу
никто не пишет.

Поля записи:
- `time` — момент события, UTC, с миллисекундами;
- `level` — `info`, `warn` или `error`;
- `category` — одно из значений таблицы ниже;
- `message` — короткое описание по-русски;
- `duration_ms` — длительность, если у операции она есть;
- `job_id` — задача, к которой относится событие, если есть;
- `details` — JSON с параметрами события.

| Категория | Что пишется | Детали |
|---|---|---|
| `app` | Запуск и закрытие приложения, версия | версия, платформа |
| `connection` | Проверка связи, потеря и восстановление связи с Forge | адрес, время простоя |
| `catalog` | Обновление списков моделей, модулей, LoRA | количество элементов, длительность |
| `checkpoint` | Смена чекпоинта или набора модулей между задачами | было, стало |
| `queue` | Задача поставлена, отменена, повторена; пауза и возобновление очереди | тип задачи |
| `generation` | Старт и завершение генерации или апскейла | чекпоинт, размер, шаги, сид, число картинок, длительность |
| `preset` | Создание, применение, изменение, удаление пресета | имя |
| `settings` | Изменение настройки | ключ, старое и новое значение |
| `storage` | Сохранение и удаление картинок, скрытие, изменение тегов | путь, размер файла |
| `lock` | Открытие и закрытие замка, неверный пароль | — |
| `error` | Любая ошибка: сеть, ответ Forge, диск, база | текст ошибки, HTTP-статус, стек |

Время генерации измеряется от отправки запроса в Forge до получения ответа и пишется в
`duration_ms` события завершения. То же значение сохраняется в задаче и показывается в
галерее рядом с картинкой.

Смена чекпоинта фиксируется, когда чекпоинт или модули очередной задачи отличаются от
предыдущей выполненной. Время, которое Forge тратит на загрузку модели, отдельно не
измеряется: API его не сообщает, оно входит в длительность первой генерации после смены.

Промпты в журнал не пишутся: они хранятся в параметрах задачи, и журнал ссылается на неё
через `job_id`.

Ошибка записи в журнал не прерывает операцию: она выводится в консоль main-процесса.

Записи старше срока хранения (по умолчанию 90 дней, меняется в настройках) удаляются при
запуске приложения. Экспорт выгружает текущую выборку в файл JSON Lines.

Тесты: `oplog` на временной базе (запись, фильтры, очистка по сроку, экспорт); тесты
`queue/runner` дополнительно проверяют, что каждый исход задачи оставляет ожидаемые
записи.

## 10. Документация проекта

Два файла в корне репозитория ведутся обязательно.

**`CHANGELOG.md`** — формат Keep a Changelog, версии по SemVer. Каждая правка поведения,
новая функция и исправление добавляет строку в раздел `Unreleased` в том же коммите, что
и код. При выпуске версии раздел `Unreleased` переименовывается в номер версии с датой.

**`README.md`** — назначение приложения, требования к Forge Neo, установка и запуск,
описание экранов и возможностей, расположение данных и журнала, команды разработки.
Обновляется в том же коммите, который меняет то, что в нём описано.

Правило проверки: изменение не считается завершённым, пока в его коммите нет записи в
`CHANGELOG.md`, а `README.md` соответствует новому поведению. Правило записывается в
`CLAUDE.md` проекта и повторяется в каждой задаче плана реализации как отдельный шаг.
Исключение — коммиты, которые не меняют поведение приложения (рефакторинг, тесты,
форматирование): для них запись в changelog не нужна.

## 11. Дизайн-система

Готовые наборы компонентов и темы (MUI, Ant, shadcn/ui, Tailwind UI) не используются:
все компоненты свои, на токенах из этого раздела. Допускаются только библиотеки без
внешнего вида: Radix Primitives для поведения диалогов, меню, слайдеров и подсказок,
Phosphor Icons для значков.

### Идея

Проявочная комната и контактный лист. Единственный источник цвета на экране — сами
картинки; интерфейс нейтральный, тёплый, почти чёрный. Цвет в интерфейсе появляется
только как сигнал. Технические значения набраны моноширинным шрифтом, как маркировка на
краю плёнки.

Три узнаваемых приёма:
1. **Проявка.** Идущая генерация — мозаика из крупных пикселей, которая уточняется с
   каждым превью и в конце переходит в готовую картинку.
2. **Маркировка кадра.** Под плиткой при наведении — строка моноширинным шрифтом: номер,
   время генерации, размер. Например `№ 0412 · 41 с · 832×1216`.
3. **Сигнальный янтарь.** Один акцентный цвет на всё приложение, только для того, что
   происходит сейчас или выбрано.

### Цвет

Все цвета заданы CSS-переменными; в компонентах сырых значений нет.

| Токен | Значение | Назначение |
|---|---|---|
| `--canvas` | `#0B0B0A` | Фон окна под галереей |
| `--surface-1` | `#141413` | Боковые панели, плитка-заглушка |
| `--surface-2` | `#1C1C1A` | Панель промпта, строки параметров, окна |
| `--surface-3` | `#262624` | Наведение, меню, подсказки |
| `--line` | `rgba(255,255,255,0.08)` | Волосяная граница |
| `--line-strong` | `rgba(255,255,255,0.16)` | Граница при наведении и у полей |
| `--text` | `#ECEAE4` | Основной текст |
| `--text-2` | `#A8A59C` | Подписи, вторичный текст |
| `--text-3` | `#8A877E` | Заглушки, маркировка кадра |
| `--paper` | `#F4F1EA` | Заливка главной кнопки; текст на ней `#11110F` |
| `--signal` | `#F2A33A` | Идущая задача, выбор, фокус, внимание |
| `--ok` | `#6FCF97` | Связь есть, часть модели найдена |
| `--blocked` | `#F0625A` | Ошибка, недостающая часть, удаление |

Правила:
- На экране одна залитая кнопка — запуск генерации, цветом `--paper`. Остальные кнопки
  без заливки.
- `--signal`, `--ok`, `--blocked` используются только для состояний и всегда вместе со
  значком или текстом, никогда одним цветом.
- Чистые `#000` и `#FFF`, градиенты, свечение и цветные фоны панелей запрещены.
- Контраст текста к фону не ниже 4.5:1; для `--text-3` на `--surface-1` он 5.1:1.

### Шрифты

Оба шрифта с кириллицей, лежат в пакете приложения; загрузки из сети нет.

- **Onest** — весь интерфейс. Начертания 400 и 500.
- **JetBrains Mono** — имена файлов, сид, числовые параметры, таймеры, маркировка кадра,
  журнал. Начертание 400, табличные цифры.

| Роль | Шрифт | Размер / интерлиньяж |
|---|---|---|
| Промпт | Onest 400 | 15 / 22 |
| Основной | Onest 400 | 13 / 18 |
| Подпись | Onest 400 | 12 / 16 |
| Заголовок панели | Onest 500 | 15 / 20 |
| Значение, маркировка | JetBrains Mono 400 | 12 / 16 |

Меньше 12 px текст не бывает. Иерархия строится размером и цветом текста; жирнее 500 и
заглавными буквами ничего не набирается.

### Форма и отступы

- Шаг сетки 4 px; отступы только из ряда 4, 8, 12, 16, 24, 32.
- Скругления: плитка 6, элемент управления 8, панель и окно 12. Полностью круглых
  «таблеток» нет, кроме точки индикатора связи.
- Зазор между плитками галереи 6 px; минимальная ширина плитки 220 px, число колонок
  считается от ширины окна.
- Высота элементов управления 28 px, в панели промпта 32 px. Кликабельная область не
  меньше 28×28 px.
- Тени нет ни у чего, кроме трёх плавающих слоёв: панель промпта, меню, окно. У них одна
  общая тень и волосяная граница.
- Размытие фона применяется в одном месте: под панелью промпта, чтобы текст читался
  поверх картинок. Сама панель непрозрачна на 92 %.
- Значки Phosphor, начертание Regular, размеры 16 и 20 px. Эмодзи не используются.

### Окно

Системного заголовка нет: кнопки окна Windows встроены в верхнюю строку приложения
(`titleBarOverlay`), строка служит областью перетаскивания. Минимальный размер окна
1100×700.

### Компоненты

- **Плитка картинки.** Только изображение, без рамки и подписи. При наведении — граница
  `--line-strong`, маркировка кадра снизу и кнопки действий сверху справа. Выделенная —
  граница 2 px `--signal`.
- **Плитка задачи.** Ждущая: `--surface-1`, пунктирная граница, порядковый номер в
  очереди. Идущая: мозаика, внизу строка `шаг 5/8 · 12 с` и линия прогресса 2 px цветом
  `--signal`. Ошибка: значок, короткий текст, кнопка «Повторить», граница `--blocked`.
- **Скрытая плитка.** `--surface-1` с диагональной штриховкой и значком замка. Размер
  плитки сохраняется, чтобы галерея не перестраивалась при открытии замка.
- **Панель промпта.** `--surface-2`, скругление 12. Поле промпта растёт до шести строк.
  Параметры — прямоугольные кнопки с подписью цветом `--text-2` и значением цветом
  `--text`.
- **Карточка модели.** Строки «роль — имя файла — статус». Имя моноширинным шрифтом.
  Статус: значок-галочка `--ok` или значок и слово «не найден» цветом `--blocked`.
- **Строка параметра.** Подпись слева, значение справа, одна высота 28 px. Числа
  меняются перетаскиванием по значению и вводом с клавиатуры.
- **Тег.** Прямоугольник со скруглением 4, текст 12 px, граница `--line`. Выбранный в
  фильтре — граница `--signal`.
- **Ползунок «до / после».** Вертикальная линия 1 px цветом `--paper` с ручкой 28 px;
  размеры сторон подписаны моноширинным шрифтом в углах.

### Движение

| Что | Длительность | Кривая |
|---|---|---|
| Наведение, нажатие | 120 мс | ease-out |
| Меню, подсказка | 160 мс | ease-out |
| Боковая панель: вход / выход | 220 / 160 мс | ease-out / ease-in |
| Мозаика → готовая картинка | 260 мс | перекрёстное растворение |
| Просмотр: плитка раскрывается на экран | 260 мс | ease-out |

Анимируются только `transform` и `opacity`. Декоративных анимаций нет: движение
показывает, откуда элемент появился и что изменилось. При системной настройке
«уменьшить движение» всё, кроме линии прогресса, переключается мгновенно.

### Клавиатура и доступность

- Видимый фокус: обводка 2 px `--signal` с отступом 2 px у каждого интерактивного элемента.
- Клавиши: `Ctrl+Enter` — запустить, `/` — поиск, `Esc` — закрыть панель или окно,
  стрелки — перемещение по плиткам, `Enter` — открыть, `H` — скрыть, `T` — теги,
  `Delete` — удалить с подтверждением.
- У кнопок-значков есть подпись для экранного диктора и всплывающая подсказка.
- Удаление картинок отменяется из уведомления в течение пяти секунд.

### Производительность

- Галерея виртуализирована: в DOM только видимые плитки и запас в один экран.
- Плитке заранее задано соотношение сторон, поэтому загрузка картинок не сдвигает сетку.
- В галерее показываются миниатюры; полный файл грузится только в просмотре.
- Превью идущей задачи обновляется не чаще раза в секунду.

### Чего не делаем

Фиолетово-розовые «нейросетевые» градиенты, неон и свечение, стекло и размытие как
украшение, тени у карточек, круглые «таблетки» на каждом элементе, спиннер вместо
прогресса с шагами, окно поверх окна, цветные панели, спорящие с картинками, шрифт Inter
и системные шрифты по умолчанию.
